Documentación: Sistema de Login Facial (Hevelab Viision ERP)

Explicación del funcionamiento y desarrollo técnico

1. ¿Cómo funciona? (Flujo del Usuario)

El sistema implementa un inicio de sesión biométrico basado en reconocimiento facial, complementado con un segundo factor de autenticación (OTP por correo). El flujo es el siguiente:

Paso 1: Captura Facial (Frontend)
El usuario accede al portal y selecciona "Iniciar sesión con rostro". La cámara web se activa mediante un modal y el sistema analiza en tiempo real el rostro utilizando inteligencia artificial en el navegador. Se requieren 4 detecciones estables para capturar los rasgos faciales.
Paso 2: Extracción de Descriptores
Una vez validado el rostro, el sistema genera un "descriptor facial" (un arreglo matemático de 128 dimensiones que representa las características únicas de la cara) y lo envía de forma segura al servidor.
Paso 3: Verificación Biométrica (Backend)
El servidor (PHP) recibe el descriptor y lo compara con los rostros registrados en la base de datos calculando la Distancia Euclidiana. El umbral de coincidencia es configurable (por defecto 0.40) y se obtiene desde config/system_config.json. Solo se consideran usuarios con verificado = 1.
Paso 4: Doble Factor de Autenticación (2FA)
Como medida de seguridad adicional, el sistema no da acceso inmediato. Genera un código OTP (One-Time Password) de 6 dígitos y lo envía al correo electrónico del usuario reconocido. La duración del OTP es configurable (por defecto 5 minutos) desde config/system_config.json.
Paso 5: Acceso al Sistema
El usuario es redirigido a una pantalla donde debe ingresar el código recibido en su correo. Si es correcto, ingresa al Dashboard principal.
Nota: El descriptor facial es un vector numérico (128 valores) y no una imagen. El procesamiento del rostro ocurre en el navegador y al servidor solo se envía el descriptor.

2. ¿Cómo se desarrolló? (Arquitectura Técnica)

El proyecto está estructurado bajo el patrón de arquitectura MVC (Modelo-Vista-Controlador). A continuación, se detallan las tecnologías y componentes clave:

PHP 8+ MySQL / PDO JavaScript (ES6) Face-API.js PHPMailer HTML5 / CSS3

2.1. Frontend (Reconocimiento en Navegador)

Se utiliza la librería face-api.js (basada en TensorFlow.js) en el archivo assets/js/face_auth.js. Se cargan tres modelos neuronales preentrenados ubicados en assets/models/:

  • SsdMobilenetv1: Para detectar dónde hay un rostro en el video de la cámara.
  • FaceLandmark68Net: Para ubicar 68 puntos clave en el rostro (ojos, nariz, boca).
  • FaceRecognitionNet: Para generar el descriptor matemático de 128 dimensiones.

Este enfoque garantiza la privacidad, ya que el procesamiento de la imagen se hace en el dispositivo del usuario y solo viajan números (el descriptor) al servidor.

2.2. Backend (API y Lógica de Negocio)

El archivo central para login facial es api/face_login.php. Su lógica interna es la siguiente:

  1. Recibe el JSON con el descriptor (array de 128 floats).
  2. Lee la configuración en config/system_config.json para obtener el umbral (face_threshold) y la expiración del OTP (otp_expiracion_min).
  3. Consulta a la base de datos (mediante PDO) usuarios con face_descriptor y verificado = 1.
  4. Ejecuta un bucle iterando sobre cada usuario para calcular la distancia euclidiana: 
    $sum = 0.0;
for ($i = 0; $i < 128; $i++) {
    $diff = (float)$inputDescriptor[$i] - (float)$stored[$i];
    $sum += $diff * $diff;
}
$dist = sqrt($sum);
  5. Identifica la menor distancia. Si es menor al umbral configurado, el usuario es validado y se dispara el envío del OTP por correo.

2.3. Seguridad y Base de Datos

  • Protección contra suplantación: Al requerir un código OTP por correo (usando PHPMailer), se mitiga el riesgo de que alguien intente ingresar usando una foto frente a la cámara.
  • Base de datos segura: Se utilizan consultas preparadas (Prepared Statements) con PDO para evitar inyección SQL (ej. al guardar el código OTP).
  • Estructura MVC: El código está ordenado en controllers/, models/, y views/, separando la lógica de datos, reglas de negocio e interfaz de usuario.

3. Nuevas implementaciones (Módulos Administrativos)

Además del flujo de autenticación, el sistema incorpora módulos para administración, monitoreo y configuración centralizada.

3.1. Panel Dashboard (métricas y monitoreo)

  • Vista: Dashboard.php
  • API: api/dashboard_data.php

Este panel consulta métricas de usuarios verificados, usuarios con biometría activa, pendientes de verificación OTP, y gráficos de registros recientes.

Incluye una tarea de limpieza automática que elimina usuarios no verificados cuyo OTP expiró hace más de 5 minutos, y también permite ejecutar la limpieza manualmente desde el panel.

3.2. Gestión de usuarios

  • Vista: views/usuarios/index.php
  • API: api/usuarios_api.php

Permite listar, crear, editar y eliminar usuarios. También permite:

  • Marcar usuarios como verificados o pendientes (suspensión lógica).
  • Eliminar el descriptor facial (obligando a re-registrar biometría si se desea usar login facial).

3.3. Configuración del sistema (umbral facial, OTP, intentos)

  • Vista: views/configuracion/index.php
  • API: api/config_api.php
  • Archivo persistente: config/system_config.json

La configuración centraliza parámetros operativos:

  • face_threshold: umbral de distancia euclidiana para coincidencia facial (a menor valor, más estricto).
  • otp_expiracion_min: minutos de expiración del OTP en login facial.
  • max_intentos_login: política de intentos máximos (control centralizado para endurecer el acceso).
Importante: Las APIs administrativas requieren sesión activa ($_SESSION['user_id']). Si no hay sesión, responden 401.

4. Endpoints principales (resumen)

Endpoint Método Descripción
api/face_login.php POST Recibe { descriptor: [128] }, valida coincidencia con face_threshold, genera OTP y redirige a verificación.
api/config_api.php?action=leer GET Devuelve la configuración actual desde system_config.json.
api/config_api.php?action=guardar POST Guarda face_threshold, otp_expiracion_min, max_intentos_login y registra auditoría (updated_at, updated_by).
api/usuarios_api.php?action=listar GET Lista usuarios con estado verificado, biometría y fechas relevantes.
api/usuarios_api.php?action=crear|editar|eliminar POST CRUD de usuarios (crear incluye hashing de contraseña).
api/usuarios_api.php?action=toggle_verificado POST Cambia el estado verificado (activo/suspendido).
api/usuarios_api.php?action=resetear_facial POST Elimina el face_descriptor del usuario.
api/dashboard_data.php?action=stats|usuarios|cleanup GET Métricas, tabla de usuarios (últimos 100) y limpieza manual de no verificados.
