Documentación: Sistema de Login Facial (Hevelab Viision ERP)

Explicación del funcionamiento y desarrollo técnico

1. ¿Cómo funciona? (Flujo del Usuario)

El sistema implementa un inicio de sesión biométrico basado en reconocimiento facial, complementado con un segundo factor de autenticación (OTP por correo). El flujo es el siguiente:

Paso 1: Captura Facial (Frontend)
El usuario accede al portal y selecciona "Iniciar sesión con rostro". La cámara web se activa mediante un modal y el sistema analiza en tiempo real el rostro utilizando inteligencia artificial en el navegador. Se requieren 4 detecciones estables para capturar los rasgos faciales.
Paso 2: Extracción de Descriptores
Una vez validado el rostro, el sistema genera un "descriptor facial" (un arreglo matemático de 128 dimensiones que representa las características únicas de la cara) y lo envía de forma segura al servidor.
Paso 3: Verificación Biométrica (Backend)
El servidor (PHP) recibe el descriptor y lo compara con todos los rostros registrados en la base de datos calculando la Distancia Euclidiana. Si la distancia entre el rostro capturado y uno almacenado es menor a 0.52, se considera una coincidencia exitosa.
Paso 4: Doble Factor de Autenticación (2FA)
Como medida de seguridad adicional, el sistema no da acceso inmediato. Genera un código OTP (One-Time Password) de 6 dígitos válido por 5 minutos y lo envía al correo electrónico del usuario reconocido.
Paso 5: Acceso al Sistema
El usuario es redirigido a una pantalla donde debe ingresar el código recibido en su correo. Si es correcto, ingresa al Dashboard principal.

2. ¿Cómo se desarrolló? (Arquitectura Técnica)

El proyecto está estructurado bajo el patrón de arquitectura MVC (Modelo-Vista-Controlador). A continuación, se detallan las tecnologías y componentes clave:

PHP 8+ MySQL / PDO JavaScript (ES6) Face-API.js PHPMailer HTML5 / CSS3

2.1. Frontend (Reconocimiento en Navegador)

Se utiliza la librería face-api.js (basada en TensorFlow.js) en el archivo assets/js/face_auth.js. Se cargan tres modelos neuronales preentrenados ubicados en assets/models/:

  • SsdMobilenetv1: Para detectar dónde hay un rostro en el video de la cámara.
  • FaceLandmark68Net: Para ubicar 68 puntos clave en el rostro (ojos, nariz, boca).
  • FaceRecognitionNet: Para generar el descriptor matemático de 128 dimensiones.

Este enfoque garantiza la privacidad, ya que el procesamiento de la imagen se hace en el dispositivo del usuario y solo viajan números (el descriptor) al servidor.

2.2. Backend (API y Lógica de Negocio)

El archivo central para esta función es api/face_login.php. Su lógica interna es la siguiente:

  1. Recibe el JSON con el descriptor (array de 128 floats).
  2. Consulta a la base de datos (mediante PDO) todos los usuarios que tienen un face_descriptor guardado.
  3. Ejecuta un bucle iterando sobre cada usuario para calcular la distancia euclidiana: 
    $sum = 0.0;
for ($i = 0; $i < 128; $i++) {
    $diff = (float)$inputDescriptor[$i] - (float)$stored[$i];
    $sum += $diff * $diff;
}
$dist = sqrt($sum);
  4. Identifica la menor distancia. Si es menor al umbral estricto de 0.52, el usuario es validado.

2.3. Seguridad y Base de Datos

  • Protección contra suplantación: Al requerir un código OTP por correo (usando PHPMailer), se mitiga el riesgo de que alguien intente ingresar usando una foto frente a la cámara.
  • Base de datos segura: Se utilizan consultas preparadas (Prepared Statements) con PDO para evitar inyección SQL (ej. al guardar el código OTP).
  • Estructura MVC: El código está ordenado en controllers/, models/, y views/, separando la lógica de datos, reglas de negocio e interfaz de usuario.
